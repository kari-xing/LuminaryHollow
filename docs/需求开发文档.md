# 1. 项目概述

## 1.1 项目背景

随着 AI 助手普及，用户对"有温度、有记忆"的对话体验需求日益增强。传统 AI 助手仅做一问一答，缺乏对用户情绪的关注与对过往对话的记忆，难以建立持续的信任与陪伴感。本项目以"AI 树洞 + 知识花园"为双项目愿景，本阶段聚焦 **AI 树洞**——情绪感知对话伙伴，为用户提供一个安全、私密、有情感连接的倾诉空间。

## 1.2 项目定位

一个有记忆、有温度、能感知情绪的 **AI 对话伙伴**。它像朋友一样记得用户说过的话，能察觉用户的情绪变化，陪伴用户梳理思路、记录心情。

## 1.3 核心理念

> 情绪被看见，心里就有了光。

让每一次倾诉都被"看见"，让情绪从混沌变清晰，从情绪中生长出洞察与力量。

## 1.4 核心差异化卖点

1. **情感感知**：对话过程中实时识别并反馈用户情绪，AI 回复携带情绪标签，界面以情绪主题色呈现。
2. **长期记忆**：多层级记忆系统（Redis 短期窗口 + ChromaDB 长期向量记忆 + PostgreSQL 用户画像），让 AI 做到"上次你说过……"式的个性化陪伴。
3. **可视化心情日记**：把抽象情绪转化为热力图、趋势曲线、关键词云、AI 周报等可量化的数据洞察。

## 1.5 项目目标

- G1：构建可实时对话、可感知情绪、带流式输出的聊天主界面。
- G2：实现三级记忆系统，支持长期记忆的存取、总结、检索与展示。
- G3：实现完整的心情日记看板（热力图 / 趋势 / 时间轴 / 词云 / 周报）。
- G4：完成 JWT 认证、多设备同步、数据导出、隐私模式等数据管理能力。
- G5：以 Docker Compose 完成一键部署并交付测试。

## 1.6 成功指标（可量化验收）

| 指标 | 目标值 |
| ---- | ------ |
| WebSocket 消息往返延迟 | P95 < 500ms（不含 LLM 推理） |
| 流式首字输出时间 | < 2s |
| LLM 单轮回复长度 | ≤ 150 字 |
| 情绪标签识别准确率 | ≥ 85%（人工抽样评测） |
| 连续 20 轮对话上下文不丢失 | 100% |
| 长期记忆检索命中率（Top-5） | ≥ 80% |
| 页面首屏加载时间 | < 3s |
| 系统可用性（开发期） | 单机稳定运行 7×24 小时 |

## 1.7 项目范围

**范围内**：聊天、记忆、看板、周报、认证、设置、导出、隐私模式、部署。

**范围外（本期不做）**：原生 App 客户端（仅 Web）、知识花园子项目、支付/商业化、多人社交、语音通话。

# 2. 用户与场景分析

## 2.1 目标用户

| 用户群体 | 描述 | 核心诉求 |
| ---- | ---- | ---- |
| 压力型用户 | 职场人、求职者、备考学生等面临阶段性压力 | 倾诉、被理解、情绪疏导 |
| 内向表达者 | 不习惯向身边人袒露情绪的人 | 安全、匿名、无评判的树洞 |
| 自我觉察者 | 希望记录心情、观察情绪变化、自我成长的人 | 情绪记录、可视化复盘、规律发现 |
| 轻量用户 | 想尝试 AI 陪伴、好奇情绪可视化的人 | 低门槛体验、易上手 |

## 2.2 典型用户画像

**画像 A：应届求职者（小舟，24 岁）**
- 场景：连续面试受挫，晚上容易焦虑，没人可说。
- 期望：向 AI 倾诉后得到共情回应；AI 记得上次聊过的面试困扰，在情绪低落时给予鼓励。
- 使用路径：注册 → 聊天倾诉 → 查看心情看板 → 收到周报。

**画像 B：自由职业者（阿黎，32 岁）**
- 场景：情绪波动大，想通过记录找到规律。
- 期望：每天快速点心情图标记录情绪，看月度趋势，发现"每到周五就焦虑"的规律。
- 使用路径：快捷情绪记录 → 看板热力图 / 趋势 → 周报洞察。

## 2.3 用户故事

| 编号 | 角色 | 故事 |
| ---- | ---- | ---- |
| US-01 | 所有用户 | 作为用户，我希望用手机号 / 邮箱注册登录，以便多设备同步我的对话 |
| US-02 | 求职者 | 作为求职者，我希望 AI 记住我上周聊过的面试焦虑，以便它在新对话中自然提及并关心 |
| US-03 | 内向者 | 作为内向者，我希望对话环境温暖安全，以便我愿意持续倾诉 |

## 2.4 核心使用场景

1. **首次倾诉**：注册 → 进入聊天页 → AI 引导填写基础画像（姓名 / 年龄 / 职业 / 目标 / 困扰，可跳过）→ 开始自由对话。
2. **持续陪伴**：再次登录 → AI 调用长期记忆自然寒暄（"上次你说面试结果这周出，今天有消息了吗？"）。
3. **情绪快记**：不聊天时点击心情图标记录当下情绪，写入看板。
4. **可视化复盘**：打开看板，查看热力图、趋势、词云，回看每日摘要。
5. **周报总结**：每周日收到 AI 生成的周报，回顾一周情绪与关注焦点。
6. **数据管理**：编辑画像、管理长期记忆、开启隐私模式、导出数据。

## 4.2 FR1 用户认证

| 需求 | 详细说明 |
| ---- | ---- |
| FR1-1 注册 | 支持手机号或邮箱注册；密码强度 ≥ 8 位且含字母和数字；手机号验证码（预留）。 |
| FR1-2 登录 | 手机号 / 邮箱 + 密码登录；签发 JWT（access token 2h + refresh token 7d）。 |
| FR1-3 鉴权 | 除 /login、/register、/ws 握手外，全部接口需携带 `Authorization: Bearer <token>`。 |
| FR1-4 会话同步 | 同一账号任意设备登录后，历史会话与长期记忆互通（数据在服务端）。 |
| FR1-5 退出登录 | 客户端删除 token 并断开 WebSocket；refresh token 加入黑名单。 |

**验收标准**：注册后可立即登录；无效 / 过期 token 返回 401；重复邮箱注册返回 409；会话记录跨设备一致。

## 4.3 FR2 聊天主界面

| 需求 | 详细说明 |
| ---- | ---- |
| FR2-1 实时对话 | 通过 `/ws/chat/{session_id}` WebSocket 通信；支持 LLM 流式打字机效果输出；断线自动重连并恢复未完成消息。 |
| FR2-2 情绪标签 | 每次 AI 回复携带情绪标签（😊开心 / 😌平静 / 😔低落 / 😤焦虑 / 😡愤怒），对应不同颜色边框 / 背景；同时输出 0~1 情绪评分。 |
| FR2-3 快捷情绪记录 | 输入框上方提供 5 个心情图标，用户点击即记录当下情绪（无需对话），写入 chat_messages（role=user, 标记为快捷打卡）。 |
| FR2-4 消息气泡 | 用户消息靠右（蓝色），AI 消息靠左（情绪主题色）；新消息带轻微淡入 / 上浮动画。 |
| FR2-5 输入框 | Enter 发送、Shift+Enter 换行；发送后输入框清空并禁用直至回复完成；单条字数上限 2000。 |
| FR2-6 输入状态 | 用户发送后、AI 输出前显示"对方正在输入…"；流式输出时实时渲染已生成的 token。 |
| FR2-7 会话管理 | 新用户进入自动创建会话；支持"新对话"；切换会话时加载历史消息。 |
| FR2-8 欢迎引导 | 首次对话展示引导卡片，邀请用户填写基础画像（可跳过）；问候语温暖自然。 |
| FR2-9 隐私提示 | 首次使用展示隐私说明；隐私模式下气泡角标显示"仅本次会话"。 |

**验收标准**：WebSocket 连接延迟 < 500ms；20 轮连续对话不丢消息；流式输出每 50~150ms 刷新一次；断网重连后消息不重复、不丢失；情绪标签与主题色正确渲染。

## 4.4 FR3 记忆系统（核心）

### 4.4.1 记忆层级

| 层级 | 技术实现 | 存储内容 | 保留时长 | 作用 |
| ---- | ---- | ---- | ---- | ---- |
| 短期记忆 | Redis 滑动窗口（List + TTL） | 最近 10 轮对话 | 当前会话（TTL 24h） | 保持对话连续性 |
| 长期记忆 | ChromaDB 向量 + PostgreSQL 摘要表 | 关键事件 / 情绪状态 / 用户偏好 | 永久（可手动删除） | 跨会话个性化 |
| 用户画像 | PostgreSQL 结构化字段 | 姓名 / 年龄 / 职业 / 长期目标 / 核心困扰 / 偏好语气 | 永久（可编辑） | 上下文基座 |

### 4.4.2 记忆调用流程

用户发消息 → 检索用户画像（PostgreSQL）→ 检索长期记忆（ChromaDB Top-K）→ 拼接近期短期记忆（Redis）→ 组装完整 Prompt → LLM 生成回复 → 解析情绪标签 / 评分 → 写回 chat_messages →（每 5 轮触发）LLM 总结 → 写入长期记忆。

### 4.4.3 记忆总结策略

- 触发条件：每满 5 轮对话触发一次异步总结（不阻塞回复）。
- 总结内容：关键事件、用户情绪状态变化、用户偏好、可长期记住的事实。
- 去重合并：总结前先检索已存在相关记忆，相似度 > 0.85 时合并更新而非新增。
- 隐私模式：开启时不触发总结、不写入长期记忆。

### 4.4.4 记忆检索策略

- 将用户最新消息向量化，在 ChromaDB 中检索 Top-5（按相似度 + 时间衰减加权）。
- 过滤条件：仅检索当前用户数据；可检索 memory_type 维度（event / emotion / preference）。
- 记忆拼入 Prompt 时附带时间信息（如"2026-08-02 说：……"），供 LLM 自然引用。

### 4.4.5 记忆管理

- 前端提供 /memories 页，列表展示长期记忆（内容 / 时间 / 类型），支持单条删除、批量清空。
- 删除记忆后立即从 ChromaDB 与 PostgreSQL 中同步移除。

**验收标准**：跨会话提问"我之前说过的面试怎么样了"，AI 能引用上轮会话内容；删除记忆后不再被召回；短期记忆滑动窗口严格保留最近 10 轮；总结触发不超过每 5 轮一次。

## 4.5 FR4 心情日记看板

| 需求 | 详细说明 |
| ---- | ---- |
| FR4-1 情绪日历热力图 | 类 GitHub 贡献图；每天一格，颜色从红（消极）→ 黄（中性）→ 绿（积极）渐变，深浅代表情绪强度；点击某天可查看当天摘要与对话；支持按年切换。 |
| FR4-2 情绪趋势折线图 | ECharts / Chart.js；展示近 30 天 / 90 天情绪波动曲线（日均情绪评分）；可叠加周平均线。 |
| FR4-3 每日摘要时间轴 | 卡片列表；每次会话结束后生成摘要：如"2026-08-06 聊了 15 分钟，主要讨论了面试焦虑，情绪：😰"；卡片展示日期、时长、主题、情绪标签。 |
| FR4-4 关键词云 | 从全部对话中提取高频词；词频映射字号 / 颜色；反映近期关注焦点；支持按周 / 月筛选。 |
| FR4-5 数据来源 | 热力图 / 趋势 / 摘要均基于 chat_messages 的 emotion_score 与 emotion_label 聚合；无数据日期显示中性色。 |

**验收标准**：热力图正确聚合每日情绪均分；30 / 90 天趋势数据正确；摘要卡片与真实会话一一对应；词云词频排序正确；页面在 2s 内完成数据渲染。

## 4.6 FR5 AI 周报

| 需求 | 详细说明 |
| ---- | ---- |
| FR5-1 生成时机 | 每周日 22:00 定时任务自动生成；批量生成全部活跃用户的周报（异步队列）。 |
| FR5-2 周报内容 | 综合本周情绪趋势（平均分 / 波动）、高频话题（词云 Top 词）、关键事件（长期记忆摘要）、整体评价与温柔建议；篇幅 150~300 字。 |
| FR5-3 展示 | /reports 页以卡片列表展示历史周报，支持查看详情与复制分享。 |
| FR5-4 幂等 | 同一周不重复生成；生成失败自动重试 2 次。 |

**验收标准**：周报在预期时间生成；内容引用真实数据（情绪分 / 话题）；同周仅一条记录；历史周报可正常浏览。

# 5. 情绪感知与 Prompt 工程

## 5.1 情绪标签体系

| 标签 | 表情 | 主题色 | 情绪评分参考区间 | 典型语境 |
| ---- | ---- | ---- | ---- | ---- |
| 开心 | 😊 | #4CAF50（绿） | 0.75 ~ 1.0 | 好消息、达成目标、心情舒畅 |
| 平静 | 😌 | #90A4AE（灰蓝） | 0.45 ~ 0.75 | 日常叙述、中性话题、状态平稳 |
| 低落 | 😔 | #2196F3（蓝） | 0.25 ~ 0.45 | 失望、疲惫、难过、挫败 |
| 焦虑 | 😤 | #FF9800（橙） | 0.10 ~ 0.30 | 担心、紧张、压力大 |
| 愤怒 | 😡 | #F44336（红） | 0 ~ 0.15 | 生气、不满、被冒犯 |

> 注：评分区间仅为映射参考；以 LLM 判定标签为主，情绪评分用于看板聚合。

## 5.2 情绪感知流程

1. 用户发送消息；
2. 后端组装 Prompt（含用户画像、长期记忆、近期对话）；
3. 在 Prompt 中要求 LLM 在回复结尾输出 `【情绪标签：xxx】` 与 `【情绪评分：x.x】`；
4. 后端解析输出，剥离标签，将结构化字段写入 chat_messages（emotion_label, emotion_score）；
5. 前端根据标签渲染气泡主题色并展示标签徽标。

## 5.3 Prompt 模板

```text
你是一个温暖、善解人意的AI朋友。以下是与当前用户的对话历史和相关信息：

【用户画像】
- 姓名：{name}，{age}岁，{occupation}
- 核心目标：{goal}
- 长期困扰：{struggle}

【长期记忆】（AI自动总结的过往重要信息）
{vector_retrieved_memories}

【近期对话】（最近10轮）
{recent_chat_history}

【当前用户情绪感知】：{detected_emotion}

请以温暖、共情的语气回复用户，自然地引用长期记忆中的信息（如"上次你说过..."），回复不超过150字。同时根据用户最后一句话判断其当前情绪，在回复结尾用【情绪标签：xxx】标注。
```

## 5.4 输出解析规则

- 回复格式：正文 + `【情绪标签：😊开心】` + `【情绪评分：0.8】`；
- 解析失败兜底：标签取"平静"、评分取 0.5，不阻塞消息展示；
- 标签枚举白名单：开心 / 平静 / 低落 / 焦虑 / 愤怒（LLM 输出映射到枚举）。

## 5.5 情绪评分

- 范围 0~1，越接近 1 情绪越积极；
- 看板聚合口径：每日情绪均分 = 当日全部消息 emotion_score 的平均值；
- 会话平均情绪写入 chat_sessions.avg_emotion_score。

# 6. 记忆系统详细设计

## 6.1 记忆层级总览

| 层级 | 载体 | 读写时机 | 生命周期 |
| ---- | ---- | ---- | ---- |
| L1 短期记忆 | Redis List（key: `chat:{session_id}:recent`） | 每轮对话读、写 | TTL 24h 滑动刷新 |
| L2 长期记忆 | ChromaDB Collection（按 user_id 分区）+ postgres.long_term_memories | 每 5 轮总结写入；对话前检索 | 永久（可删除） |
| L3 用户画像 | postgres.user_profiles | 每次对话读取；用户编辑时更新 | 永久（可编辑） |

## 6.2 短期记忆（Redis）

- 数据结构：`RPUSH chat:{session_id}:recent <message_json>`，随后 `LTRIM` 至最近 10 条，`EXPIRE 86400`；
- 消息 JSON：`{"role":"user|assistant","content":"...","emotion_label":"...","ts":...}`；
- 读取：`LRANGE 0 -1` 逆序组装为最近 10 轮；
- 会话结束时保留（TTL 自然过期），下次会话由长期记忆提供跨会话上下文。

## 6.3 长期记忆（ChromaDB + PostgreSQL）

- 写入流程：LLM 总结 → 生成 embedding（Ollama embedding 模型或 API）→ 存入 ChromaDB（metadata: user_id, memory_type, created_at, postgres_id）→ 同步写 PostgreSQL long_term_memories（含 summary）。
- 检索流程：用户消息 embedding → `collection.query(query_texts=[msg], n_results=5)` → 按 user_id 过滤 → 读取摘要文本拼入 Prompt。
- 去重合并：与已有记忆 cosine > 0.85 时，更新原记录而非新增（更新 embedding 与 summary）。
- 删除：删除时按 postgres_id 同时删除 ChromaDB 中对应记录。

## 6.4 用户画像（PostgreSQL）

| 字段 | 说明 | 获取方式 |
| ---- | ---- | ---- |
| name / age / occupation | 基本信息 | 首次引导填写 / 设置页编辑 |
| goal / struggle | 长期目标 / 核心困扰 | 首次引导填写（可跳过） |
| preferred_tone | 偏好语气（warm / gentle / encouraging） | 设置页选择，默认 warm |

## 6.5 记忆调用流程（时序）

用户发消息 → ① 查 user_profiles → ② ChromaDB 检索 Top-5 长期记忆 → ③ Redis 取最近 10 轮 → ④ 组装 Prompt → ⑤ LLM 生成 → ⑥ 解析情绪标签 → ⑦ 写 chat_messages、更新会话状态 → ⑧ 异步：每 5 轮触发总结写长期记忆。

## 6.6 隐私模式

- 开启时：跳过步骤 ②⑦⑧ 中的长期记忆写入与总结、不更新画像，短期记忆照常；
- 看板数据：仅聚合非隐私模式产生的消息，隐私模式消息标记 `is_private=true` 不参与统计；
- UI：设置页开关 + 会话气泡角标提示。

# 9. 数据库设计

## 9.1 ER 概览

- `users` 1—1 `user_profiles`（用户画像）
- `users` 1—N `chat_sessions`（会话）
- `chat_sessions` 1—N `chat_messages`（消息）
- `users` 1—N `long_term_memories`（长期记忆，含向量）
- `users` 1—N `weekly_reports`（周报）

## 9.2 表结构 DDL

```sql
-- 扩展向量支持（PostgreSQL + pgvector，可选；或由 ChromaDB 承载向量）
-- CREATE EXTENSION IF NOT EXISTS vector;

-- 用户表
CREATE TABLE users (
    id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    username      VARCHAR(64)  NOT NULL,
    email         VARCHAR(255) UNIQUE,
    phone         VARCHAR(20)  UNIQUE,
    password_hash VARCHAR(255) NOT NULL,
    created_at    TIMESTAMP NOT NULL DEFAULT NOW(),
    last_active   TIMESTAMP NOT NULL DEFAULT NOW()
);

-- 用户画像表
CREATE TABLE user_profiles (
    id             UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id        UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    name           VARCHAR(64),
    age            INT CHECK (age BETWEEN 5 AND 120),
    occupation     VARCHAR(64),
    goal           TEXT,
    struggle       TEXT,
    preferred_tone VARCHAR(20) DEFAULT 'warm',
    updated_at     TIMESTAMP NOT NULL DEFAULT NOW()
);

-- 会话表
CREATE TABLE chat_sessions (
    id                UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id           UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    started_at        TIMESTAMP NOT NULL DEFAULT NOW(),
    ended_at          TIMESTAMP,
    message_count     INT DEFAULT 0,
    avg_emotion_score FLOAT,
    summary           TEXT            -- 会话摘要（供看板时间轴使用）
);

-- 消息表
CREATE TABLE chat_messages (
    id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    session_id    UUID NOT NULL REFERENCES chat_sessions(id) ON DELETE CASCADE,
    role          VARCHAR(10) NOT NULL CHECK (role IN ('user','assistant','system')),
    content       TEXT NOT NULL,
    emotion_label VARCHAR(20),
    emotion_score FLOAT CHECK (emotion_score BETWEEN 0 AND 1),
    is_private    BOOLEAN DEFAULT FALSE,   -- 隐私模式标记
    created_at    TIMESTAMP NOT NULL DEFAULT NOW()
);

-- 长期记忆表（向量存放于 ChromaDB，此处存摘要与关联）
CREATE TABLE long_term_memories (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id     UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    content     TEXT,                      -- 原始相关内容（可选）
    summary     TEXT NOT NULL,             -- LLM 总结文本
    embedding   VECTOR(768),               -- 可选：若使用 pgvector；否则存于 ChromaDB
    memory_type VARCHAR(20) DEFAULT 'event',  -- event / emotion / preference
    created_at  TIMESTAMP NOT NULL DEFAULT NOW()
);

-- 周报表
CREATE TABLE weekly_reports (
    id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id       UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    week_start    DATE NOT NULL,
    week_end      DATE NOT NULL,
    summary       TEXT NOT NULL,
    emotion_trend JSON,                -- 本周每日情绪评分数组
    top_topics    JSON,                -- 高频话题 Top 词
    generated_at  TIMESTAMP NOT NULL DEFAULT NOW(),
    UNIQUE (user_id, week_start)
);
```

## 9.3 索引与性能

```sql
CREATE INDEX idx_sessions_user    ON chat_sessions(user_id, started_at DESC);
CREATE INDEX idx_messages_session ON chat_messages(session_id, created_at);
CREATE INDEX idx_messages_emotion ON chat_messages(user_id, created_at);  -- 看板聚合
CREATE INDEX idx_memories_user    ON long_term_memories(user_id, created_at DESC);
CREATE INDEX idx_reports_user     ON weekly_reports(user_id, week_start DESC);
```

- 看板聚合可选用物化视图：`mv_daily_emotion(user_id, date, avg_score, label_mode)`；

# 10. API 接口设计

## 10.1 通用约定

- 基础路径：`/api`；数据格式：`application/json`；
- 认证：`Authorization: Bearer <access_token>`；
- 统一响应：成功返回业务数据；失败返回 `{"code": <业务码>, "message": "..."}`；
- 分页：`?page=1&page_size=20`，返回 `{"items": [], "total": n, "page": 1}`。

## 10.2 认证接口

### POST /api/auth/register —— 用户注册
```json
// 请求
{ "username": "xiaozhou", "email": "x@qq.com", "password": "pass1234" }
// 响应 201
{ "id": "uuid", "username": "xiaozhou", "created_at": "2026-08-07T10:00:00Z" }
// 错误：409 邮箱已存在；422 参数校验失败
```

### POST /api/auth/login —— 用户登录
```json
// 请求
{ "account": "x@qq.com", "password": "pass1234" }
// 响应 200
{ "access_token": "eyJ...", "refresh_token": "eyJ...", "token_type": "bearer" }
// 错误：401 账号或密码错误
```

### POST /api/auth/refresh —— 刷新 token
```json
{ "refresh_token": "eyJ..." } → { "access_token": "eyJ..." }
```

## 10.3 WebSocket 协议

- 端点：`/ws/chat/{session_id}?token=<jwt>`；
- 握手：校验 token；校验 session 归属；
- 消息类型（JSON）：

```json
// 客户端 → 服务端
{ "type": "user_message", "content": "今天面试又挂了，好难过" }
{ "type": "quick_checkin", "emotion_label": "焦虑" }

// 服务端 → 客户端
{ "type": "typing", "session_id": "..." }                              // 正在输入
{ "type": "stream_chunk", "content": "你" }                            // 流式分片
{ "type": "stream_end", "emotion_label": "低落", "emotion_score": 0.3 }
{ "type": "error", "code": 5001, "message": "LLM 服务不可用" }
{ "type": "ping" }   // 心跳，客户端回 pong
```

- 断开策略：服务端保留会话状态；重连后前端重新拉取最近消息并比对去重。

# 14. 部署方案

## 14.1 Docker Compose 编排

```yaml
services:
  postgres:
    image: postgres:15-alpine
    environment: { POSTGRES_DB: hollow, POSTGRES_USER: hollow, POSTGRES_PASSWORD: ${DB_PASSWORD} }
    volumes: [ pgdata:/var/lib/postgresql/data ]
  redis:
    image: redis:7-alpine
  chromadb:
    image: chromadb/chroma:latest
  backend:
    build: ./backend
    environment:
      DATABASE_URL: postgresql://hollow:${DB_PASSWORD}@postgres/hollow
      REDIS_URL: redis://redis:6379/0
      CHROMA_URL: http://chromadb:8012
      LLM_BASE_URL: ${LLM_BASE_URL}
      JWT_SECRET: ${JWT_SECRET}
    depends_on: [postgres, redis, chromadb]
  frontend:
    build: ./frontend
  nginx:
    image: nginx:alpine
    ports: ["80:80"]
    volumes: [ ./nginx.conf:/etc/nginx/nginx.conf ]
    depends_on: [backend, frontend]
volumes:
  pgdata:
```

## 14.2 环境变量清单

| 变量 | 说明 |
| ---- | ---- |
| JWT_SECRET | token 签名密钥 |
| DATABASE_URL / REDIS_URL / CHROMA_URL | 各存储连接串 |
| LLM_BASE_URL / LLM_API_KEY / LLM_MODEL | LLM 服务地址 / 密钥 / 模型 |
| EMBEDDING_MODEL | embedding 模型 |
| WEEKLY_REPORT_CRON | 周报 cron 表达式（默认 `0 22 * * 0`） |

## 14.3 生产部署

- Nginx：静态资源 + `/api` 反向代理 + WebSocket 升级头；
- 后端多 worker（uvicorn --workers 4）置于 Nginx 后；
- HTTPS：Let's Encrypt 证书；
- 日志：stdout JSON 日志 + 集中采集（可选 Loki）。

## 14.4 监控告警（可选）

- 健康检查：`GET /health`（DB / Redis / Chroma 连通性）；
- 指标：连接数、消息延迟、LLM 错误率、队列积压；
- 告警：LLM 连续 5 次失败、WebSocket 掉线率异常。
